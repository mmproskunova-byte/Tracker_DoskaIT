 ТЕХНИЧЕСКОЕ ЗАДАНИЕ ДЛЯ ТРЕКИНГА (ФУНКЦИОНАЛ MVP)
-----------------------------------------------------------
IT-разработка
- Боль: задачи теряются в Telegram, дедлайны срываются
- Роли: PM, разработчик, тестировщик, заказчик
- Колонки: Бэклог -> В работе -> Ревью -> Тест -> Готово

1. РОЛИ И ПРАВА ДОСТУПА

Роль: PM (администратор)
- Видит: все задачи, все колонки, всех пользователей
- Может: создавать/удалять задачи, двигать по доске, назначать исполнителей, редактировать

Роль: Разработчик
- Видит: только свои задачи + бэклог (без исполнителя)
- Может: двигать свои задачи по колонкам «В работе» -> «На ревью», комментировать

Роль: Тестировщик
- Видит: задачи в колонке «Тестирование»
- Может: двигать свои задачи «Тестирование» -> «Готово» / «В работу» (с комментарием о баге)

Роль: Заказчик (шеф)
- Видит: только колонку «Готово» и сводку по статусам
- Может: просмотр без редактирования


2. КОЛОНКИ КАНБАН-ДОСКИ

1. Бэклог — задачи без исполнителя и срока
2. В работе — у задачи есть исполнитель и срок
3. На ревью — разработчик закончил, ждёт проверки PM
4. Тестирование — передано тестировщику
5. Готово — протестировано и принято


3. ПОЛЯ КАРТОЧКИ ЗАДАЧИ

- Название (обязательно)
- Описание (опционально)
- Приоритет: Высокий / Средний / Низкий
- Исполнитель (выпадающий список ролей)
- Дедлайн (дата)
- Дата создания (автоматически)


4. ПРАВИЛА ПЕРЕХОДОВ

- Из «Бэклога» в «В работу» — только PM может назначить исполнителя
- Из «В работе» в «На ревью» — может только исполнитель
- Из «На ревью» в «Тестирование» — только PM
- Из «Тестирование» в «Готово» — только тестировщик
- Возврат назад (например, с багом) — с обязательным комментарием


5. УВЕДОМЛЕНИЯ

- При назначении исполнителя — уведомление пользователю
- При приближении дедлайна (за 1 день) — подсветка карточки красным
